NOTE / 002

点开一个链接之后

2026 年 10 月 8 日　文陶　／　计算机网络

首页上放了几个外部链接。平常点击一下就过去了，这次顺着课程里的内容，把访问网页的过程记一下。下面说的是一次普通的 HTTPS 访问，缓存、连接复用等情况会让实际过程更短。

先找到地址

网址里写的是域名，连接网络时需要的是 IP 地址。如果没有可用的缓存结果，就要进行 DNS 查询，把域名解析成地址。浏览器也可能已经保留了连接，直接继续使用。

发出请求

对于通过 TCP 传输的 HTTPS 连接，建立 TCP 连接以后还需要完成 TLS 握手。HTTP/3 使用 QUIC，建立连接的过程有所不同，所以不能把所有网页访问都套成同一个步骤表。

接下来，浏览器发送 HTTP 请求。打开一张普通网页，通常会使用 GET 方法。服务器返回状态码、响应头和页面内容。200 表示这次请求成功，404 表示没有找到所请求的资源。

网址中的 https:// 说明使用 HTTPS；具体协商到哪个 HTTP 版本，还得看这次连接的记录。

页面慢慢出现

拿到 HTML 文件只是开始。浏览器解析文档后，发现页面还引用了样式表和图片，就会请求这些资源，再把文字、颜色和图片排到屏幕上。

本站的首页引用了一份 CSS 和一张照片。它们是独立文件，各自有请求记录。照片存放在本站，打开首页时不需要再去图片来源网站下载它。

看看 HTTP 版本

  1. 打开浏览器开发者工具，切换到“网络 / Network”。
  2. 刷新页面，找到类型为“文档 / Document”的那条请求。
  3. 显示“协议 / Protocol”列，读取该请求的实际协议。

例如，h2 表示 HTTP/2，h3 表示 HTTP/3。记录时也应该写下访问时间和客户端，因为同一个网站在不同客户端、不同网络条件下，可能协商到不同的版本。

做这类检查时，最有用的是一次真实请求的记录。单看网页源码，不能判断服务器和浏览器刚才协商了什么协议。

参考：MDN：HTTP 概述；RFC 9110：HTTP Semantics。
